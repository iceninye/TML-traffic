# 列車位置演算法 (ALGORITHM)

**版本**：v0.3.0 · **日期**：2026-10-04
資料來源同時間表數字見 [`MODEL.md`](MODEL.md)；本文講由「港鐵 API 回應」到「畫面上一粒列車」嘅完整計算流程。

港鐵**冇公開列車位置**，只公佈每個站「下一班車幾分鐘後到」。所以每粒列車都係推算出嚟，唔係 GPS。

## 總覽

```
每 18 秒
  ① 讀取 27 個站嘅 Next Train API ─────────── lib/mtr-feed.js
  ② 解析：每個站、每個方向、每班車 → 到站時刻 ── lib/mtr-schedule.js
  ③ 串連：同一班車喺唔同站嘅倒數串成一條鏈 ──── lib/mtr-estimate.js
  ④ 學習：用鏈入面相鄰兩站嘅時間差校正站間行車時間 ─ lib/tml-model.js  learn()
  ⑤ 擬合：用鏈入面所有倒數，求列車「由起點開出嘅時刻 t0」─ fitOrigin()
  ⑥ 追蹤：同上一輪嘅列車配對，t0 平滑，計延誤 ──── lib/tml-motion.js  update()
每一格畫面（60 fps）
  ⑦ 位置：由 t0 + 時間表（行車 + 停站 + S 曲線）計出而家喺邊 ─ position()
  ⑧ 平滑：新舊位置差慢慢收斂，唔跳位、唔倒行 ──── frame()
  ⑨ 繪畫：路綫圖（里程 → y 座標）／地圖（里程 → OSM 路軌經緯度）── assets/app.js
```

## ① 讀取

瀏覽器直接讀 `rt.data.gov.hk/v1/transport/mtr/getSchedule.php?line=TML&sta=XXX`（CORS 開放，唔使後端）。
每輪讀「超過 20 秒未更新」嘅站，最多 4 個同時；遇到 429 / 5xx 會停 45 秒，避免打爆 API。
某站一時回應空白會重試一次；仍然空白就沿用上一次（最多 3 分鐘）。

## ② 解析

每個站回應 `UP`（往屯門）同 `DOWN`（往烏溪沙）各最多 4 班車：`dest`、`plat`、`ttnt`（分鐘）、`time`（到站時刻）。

- **到站時刻**用 `time`，唔用 `ttnt`（報告 4.1 節）。實測 `time` 其實等於 `curr_time + ttnt 分鐘`，所以精度仍然係整分鐘；
  呢個「四捨五入到分鐘」嘅誤差（±30 秒）係後面幾步要處理嘅主要雜訊。
- `ttnt = 0` 嘅讀數會記住**第一次見到 0 嘅時刻**，唔會每輪重設（否則列車會一直停喺站入面）。

## ③ 串連（同一班車喺唔同站）

同一方向、同一目的地嘅讀數，按站序排好，逐個試接：如果 B 站嘅到站時刻 ≈ A 站到站時刻 + 時間表（A 站停站 + A→B 行車），
誤差喺每站 75 秒內，就當係同一班車。結果係一條「鏈」：例如一班往烏溪沙嘅車，喺尖東 2 分、紅磡 4 分、何文田 5 分 … 共 6–10 個讀數。

## ④ 學習站間行車時間（v0.3 新增）

時間表只有一套站間時間，而且上下行共用。但港鐵自己嘅倒數知道真實值：
一條鏈入面相鄰兩站 k、k+1，`due(k+1) − due(k) − 停站(k)` 就係港鐵預計嘅 k→k+1 行車時間（分方向）。

- 每個樣本有 ±60 秒整分鐘誤差，但每輪每段有約 20 個樣本。
- 用遞減平均（每個新樣本前，舊數 × 0.985）並向時間表收縮（加 8 個「時間表樣本」先驗），1–2 分鐘內收斂到幾秒。
- 修正值上限 ±120 秒；繁忙同非繁忙分開學；結果存喺瀏覽器 localStorage，下次開唔使由零學起。
- 實測最大修正：**烏溪沙 → 馬鞍山 −65 秒**（時間表 185 秒係「慢速駛入總站」，出站其實快一分鐘）、紅磡 → 尖東 +33 秒、美孚 → 南昌 −29 秒。

## ⑤ 擬合起點時刻 t0（v0.3 新增）

v0.2 只用鏈入面**最近一個站**嘅倒數做錨點，所以位置帶住嗰一個讀數嘅 ±30 秒誤差。v0.3 用晒成條鏈：

1. 每個讀數「k 站 d 時刻到」→ 推出 `t0 = d − 累積時間(起點→k)`（累積時間 = 各段行車 + 中途停站，已含 ④ 嘅修正）。
2. 每個讀數一個權重：最近嘅站最可信，每遠一個站權重 ÷ (1 + 0.6 × 站數差)；`ttnt = 0` 嘅讀數 × 1.5。
3. 先求加權中位數，丟走同中位數相差 > 90 秒嘅讀數（多數係串錯咗另一班車），再求加權平均 → t0。

唔同站嘅整分鐘捨入落喺唔同位置，平均之後互相抵消一部分。

## ⑥ 追蹤同延誤

**配對**：新一輪每班車，同上一輪同方向、同目的地、2.6 km 內最近嘅列車配對（由最前嗰班開始配，避免後車搶前車）。
配唔到嘅舊列車按原來 t0 繼續行 25 秒先消失；配唔到嘅新列車開一個新 id。

**t0 平滑**：`t0 = 舊 t0 + 0.4 × (新擬合 − 舊 t0)`。即係每輪只信新數 40%，捨入雜訊會喺幾輪之間平均掉。
如果一次跳超過 180 秒（真係停咗車，或者配錯咗另一班），就直接用新數，並重新開始計延誤。

**延誤**（報告 4.2 節；顯示門檻 60 秒）——三個來源取最大：

| 來源 | 計法 | 意思 |
|---|---|---|
| 行車 | `t0 現在 − t0 第一次見` | 自從開始追蹤，呢班車比時間表行車＋停站時間慢咗幾多 |
| 港鐵預報 | 鏈入面遠站推出嘅 t0 比最近站推出嘅晚幾多（中位數，扣 30 秒捨入餘量） | 港鐵自己預計佢前面會再慢 |
| 班距 | `t0 − 前一班同方向同起點列車 t0 − 時段班距`（班距按 TML1100B / 6090A / 7090 時段） | 同前車距離拉得太開；超過 2.5 個班距當係漏咗班車，唔計 |

≥ 60 秒就喺列車上面標紅色「Delay 75s」，列車卡顯示來源。港鐵 API 嘅 `isdelay = Y` 另外用黃色外框標示。

驗證：正常星期日晚 27 班車全部 < 60 秒（最大 30 秒），冇誤報；人工令一班車遲 90 秒，兩輪（約 40 秒）後顯示 60 秒，最後穩定喺 90 秒。

## ⑦ 位置（每格畫面）

已知 t0 同而家時間 `now`，`經過 = now − t0`，沿路逐段扣：

```
起點 ─行車(1→2)─ 2站停站 ─行車(2→3)─ 3站停站 ─ …
```

- 扣到落喺某段**行車**入面 → 列車喺兩站之間；段內用**梯形速度曲線**（頭 22% 時間加速、尾 22% 減速、中間定速）
  將「時間比例」轉成「距離比例」，即報告 5.2 節嘅 S 曲線：出站慢、中段快、入站前減速。
- 扣到落喺**停站** → 列車停喺站。
- `經過 < 0` → 未開出，喺起點候發（半透明）。
- 去到終點停 40 秒後移除（短程車例如往大圍同樣處理）。

結果係一個「由屯門起計嘅軌道里程」（0–56.30 km）。

## ⑧ 平滑

新一輪令目標位置突然變咗（v0.2 實測，如果唔處理，中位會跳 224 m、最大 1.1 km）。處理方法：

- 新舊位置差記做 `offset`，以 5 秒時間常數指數衰減；
- 衰減速度上限 45 m/s（即係最多「行快少少」，唔會成粒飛過去）；
- **永遠唔倒行**：如果估算落後，列車原地等估算追上。

## ⑨ 繪畫

- **路綫圖**：每站 y 座標 = 上一站 + max(62 px, 24 px × 公里)；站與站之間線性插值。上行畫左軌、下行畫右軌；同一軌上太近就沿軌錯開 21 px。
- **地圖**：里程 → OSM 真實路軌上嘅點（站與站之間按路軌長度比例）；再按 zoom 計像素偏移，上行靠右、下行靠左，貼住自己顏色嗰條綫。

## 準確度（2026-10-04 星期日 19:44–19:48，真實 feed，12 個快照）

做法：用較早快照預測各站到站時刻，再同 40 秒至 7 分鐘後快照入面 `ttnt ≤ 1` 嘅讀數比較（只用較早資料學習，即係真正「預測」）。
注意「答案」本身都係整分鐘，所以誤差下限大約 15–20 秒。

| 預測距離 | 方法 | 中位誤差 | p90 | RMS |
|---|---|---|---|---|
| 40–130 秒後 | v0.2 單一錨點 | 21.0 s | 45.0 s | 27.7 s |
| | **v0.3 擬合 + 學習** | **17.3 s** | **36.6 s** | **23.8 s** |
| 2–7 分鐘後 | v0.2 單一錨點 | 20.0 s | 45.0 s | 30.0 s |
| | v0.3 只擬合 | 17.9 s | 42.6 s | 26.1 s |
| | **v0.3 擬合 + 學習** | **16.6 s** | 47.6 s | 26.5 s |

短程預測 RMS 改善約 14%、p90 改善約 19%。長程預測中位數改善，但 p90 嘅學習效果仲未穩定（只學咗 3.7 分鐘），要更長時間數據先下定論。

## 已知限制

- 冇真實列車位置可以對答案；以上準確度係「同港鐵自己之後嘅倒數比」。
- 公眾假期當平日處理（影響繁忙判斷同班距）。
- 車廠出車冇獨立模型：喺中途站突然出現嘅列車，由該站推算返起點時刻。
- 「班距延誤」假設班次平均；時間表本身有唔平均嘅班距（例如 6 / 7 分交替）時，可能偏高最多 30 秒（仍低於 60 秒門檻）。
