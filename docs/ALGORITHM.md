# 列車位置演算法 (ALGORITHM)

**版本**：v0.4.0 · **日期**：2026-10-04
**依據**：港鐵屯馬綫工作時間表 TML1100B（平日）、TML6090A（星期六）、TML7090（星期日及公眾假期），
以及港鐵 Next Train API 實測。v0.3 嘅做法見文末「舊版比較」。

港鐵**冇公開列車位置**。API 只話「X 站下一班往 Y 嘅車 N 分鐘後到」。
v0.4 嘅原則：**API 話列車喺邊，就係喺邊；時間表只負責填補兩個讀數之間嘅細節。**

---

## 1. 資料

### 1.1 工作時間表（`tools/parse_timetables.py` → `data/tml-schedule-*.json`）

三份 PDF 每份都有：

| 部分 | 內容 | 用途 |
|---|---|---|
| A | 每段、**每個方向**、四個時段嘅行車及停站秒數 | 後備模型嘅行車時間 |
| C | 每個方向嘅班距時段 | 頂部「班距約 X 分」 |
| F | 首尾班車 | 驗證解析結果 |
| H | **每一班車喺每一個站嘅時間**（平日 527 班、星期六 433 班、星期日 378 班） | 主要定位依據 |

解析驗證：三份時間表首尾班車同 F 部分完全一致（05:45 屯門、05:38 烏溪沙、00:15、00:39）；
0 班車站序錯誤、0 班車時間倒退。

時間表揭示咗 v0.3 無法處理嘅情況：好多班車**唔係由總站開出**——
平日有 18 班由八鄉車廠經錦上路入綫、12 班由荃灣西、11 班由大圍開出；亦有大量短程車（往大圍、紅磡、鑽石山…）。

### 1.2 API 讀數嘅真正意思（實測）

將 2026-10-04 星期日晚 20 個快照、約 4,000 個讀數同 TML7090 逐班對照：

```
ttnt = ceil( (時間表到站時間 + 延誤 − 而家) / 60 )
```

- **「2 分鐘」= 1 分鐘以上、2 分鐘以內到站**，即係向上取整，唔係四捨五入。
  v0.3 當「2 分鐘」= 準時 2 分鐘後到，所以全部列車系統性**遲 30–38 秒**。
- 單一個全綫延誤值已經吻合 85% 讀數；近站（0–2 分鐘）讀數同時間表吻合約 90%。
- `ttnt = 0` 表示列車已到站（停站中）。
- 遠站讀數（3 分鐘以上）有約 10% 會差 ±1 分鐘，所以權重較低。

## 2. 演算法

```
每 20.5 秒（讀晒 27 個站）
  ① 辨認今日用邊份時間表
  ② 每個讀數對應時間表上嘅一班車
  ③ 每班車：由所有讀數求延誤
  ④ 對唔到班次嘅讀數 → 後備模型
每一格畫面（60 fps）
  ⑤ 位置 = 該班車時間表 + 延誤
  ⑥ 平滑：調校列車自身時鐘，唔郁位置
```

### ① 今日時間表

先按日曆揀（平日／星期六／星期日），然後用近站讀數驗證：
每份時間表計「讀數同最近班次相差 ≤ 40 秒」嘅比例。另一份明顯較好（多 25 個百分點以上）就自動轉用。
實測星期日晚：TML7090 **95%**、平日 36%、星期六 27%。公眾假期（行星期日時間表）因此會自動認出，唔使假期表。

### ② 讀數對應班次

- 同一個站、同一方向、**同一目的地**嘅讀數，只會對應目的地相同嘅班次（短程車因此唔會撈亂）。
- 先用全綫近站讀數求「全綫延誤」中位數，再將每個讀數對應到「扣除全綫延誤後」最近嘅班次（±4 分鐘內）。
- 同一個站牌上嘅幾個讀數唔可以對應同一班車。

實測：每個快照 30–32 班車，**100% 讀數都對應到時間表班次**。

### ③ 每班車嘅延誤

由 1.2 嘅規則，每個讀數將該班車嘅延誤限制喺一個 60 秒區間：

```
延誤 ∈ ( 讀數時刻 − 60 − 時間表到站 , 讀數時刻 − 時間表到站 ]
```

一班車通常喺 4–10 個站有讀數，加埋過去 75 秒嘅快照，就有十幾個區間。
取「被最多區間（加權）覆蓋」嘅範圍中點做延誤：近站讀數權重 1、3–5 分鐘 0.4、更遠 0.15；舊快照 × 0.7。
唔同站嘅區間捨入位置唔同，交疊之後通常收窄到 10–20 秒；個別錯配讀數會被多數票否決。

### ④ 後備模型

對唔到任何班次嘅讀數（特別車務、嚴重延誤、時間表以外嘅加班車）用 v0.3 嘅方法：
串連各站讀數 → 擬合起點時間 → 行車模型。行車及停站時間改用**當刻前後 30 分鐘時間表班次嘅實際中位數**（分方向），
再加 API 即時學習嘅修正。實測正常服務下後備模型使用率為 0。

### ⑤ 位置

時間表時刻 `τ = 而家 − 延誤`，喺該班車嘅站表中搵：

| τ 落喺 | 顯示 |
|---|---|
| 首站到站之前 | **唔顯示**（仲喺車廠／側綫） |
| 首站，開車前 | 停喺月台「即將開出」：總站最多提前 5 分鐘（折返停留），車廠出車站 2 分鐘 |
| 兩站之間 | 按時間比例用 S 曲線（加速 22%、巡航、減速 22%）放喺軌道上 |
| 中途站，到站至開車 | 停站 |
| 終點到站後 | 停 30 秒後移除 |

每段行車時間、每站停站時間都係**該班車本身**嘅時間表數字（分方向、分時段），唔係平均值。

### ⑥ 平滑（時間域）

新快照改變延誤估算時，**唔改列車位置，改列車時鐘**：
畫面用嘅延誤值以最多每秒 0.5 秒追向新估算，即係列車暫時以時間表 0.5–1.5 倍速度行。

- 列車永遠唔會倒行、唔會瞬移；
- 唔會「停喺兩站中間」——v0.3 遇到估算落後時會原地凍結等估算追上，即係用戶見到嘅停喺站與站之間；
- 喺站入面只會停耐少少或者短少少。
- 相差超過 150 秒（重新配對）先直接跳過去。

### 延誤標示

時間表班次：延誤 = ③ 嘅估算值（同官方時間表比）。
- 60–179 秒：列車變紅色，標示「- 75s」；
- 180 秒或以上：列車深紅色加白邊，光暈閃爍（系統設定「減少動態」時改為粗白邊，唔閃）。
後備模型：沿用 v0.3（行車漂移／API 預報／班距）三者取大。
API 嘅 `isdelay = Y` 另以黃框標示。

## 3. 準確度（2026-10-04 星期日 22:40–22:47，20 個真實快照，離線重播）

**方法**：用較早快照預測各站到站時間，同 40 秒至 7 分鐘後快照入面 `ttnt ≤ 1` 嘅讀數比較；
答案按 1.2 取區間中點（讀數時刻 − 30 秒）。答案本身有 ±30 秒捨入，所以誤差中位數嘅下限大約 15 秒。

| 預測距離 | 方法 | 中位誤差 | p90 | RMS | 系統偏差 |
|---|---|---|---|---|---|
| 40–130 秒 | v0.3 | 39.3 s | 69.2 s | 45.2 s | +37.9 s |
| | **v0.4** | **16.0 s** | **34.0 s** | **22.6 s** | **+1.3 s** |
| 2–7 分鐘 | v0.3 | 33.1 s | 67.0 s | 42.4 s | +33.0 s |
| | **v0.4** | **16.5 s** | **41.5 s** | **26.1 s** | **−3.0 s** |

**同 API 一致性**：同一快照入面，畫面列車到站時間落喺 API 讀數區間（±35 秒）內嘅比例：v0.3 **57%** → v0.4 **90%**。

**動畫重播**（2,019 格，每格 0.2 秒）：倒行 0 次、單格跳超過 60 m 0 次、
行車中停定 ≥ 5 秒 0 次、喺首站以外顯示「候發」0 次。

## 4. 已知限制

- 冇真實列車位置可對答案；準確度係「同港鐵之後嘅倒數比」。
- 個別列車遲超過半個班距（約 3 分鐘）時，可能被當成下一班車：位置仍然正確，但「Delay」數字會偏細。
- 時間表要人手更新：港鐵出新版（例如 TML1100C）時，用 `tools/parse_timetables.py` 重新生成。
- 特別車務（賽馬、颱風、活動）有獨立時間表；冇嗰份時間表時會落後備模型。

## 5. 舊版比較

| | v0.3 | v0.4 |
|---|---|---|
| 基準 | 自製行車模型（上下行共用一套時間） | 官方工作時間表，每班車、每站 |
| API 讀數解讀 | 「N 分鐘」= 準時 N 分鐘後 | 「N 分鐘」= (N−1, N] 分鐘內（實測） |
| 列車起點 | 一律由總站 | 按時間表：總站、車廠、側綫 |
| 用 API 嘅方法 | 加權平均擬合起點時間 | 每個讀數一個區間，多數覆蓋 |
| 平滑 | 位置差值衰減 + 唔倒行（會凍結） | 調校列車時鐘 0.5–1.5 倍（唔凍結） |
| 延誤 | 推算三項取大 | 直接對比官方時間表 |
