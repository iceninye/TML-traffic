# 列車位置演算法 (ALGORITHM)

**版本**：v0.4.0 · **日期**：2026-10-04
**依據**：港鐵屯馬綫工作時間表 TML1100B（平日）、TML6090A（星期六）、TML7090（星期日及公眾假期），
以及港鐵 Next Train API 實測。v0.3 嘅做法見文末「舊版比較」。

港鐵**冇公開列車位置**。API 只話「X 站下一班往 Y 嘅車 N 分鐘後到」。
v0.4 嘅原則：**API 話列車喺邊，就係喺邊；時間表只負責填補兩個讀數之間嘅細節。**

## 1. 資料

### 1.1 工作時間表（`tools/parse_timetables.py` → `data/tml-schedule-*.json`）

三份 PDF 每份都有：

| 部分 | 內容 | 用途 |
|---|---|---|
| A | 每段、**每個方向**、四個時段嘅行車及停站秒數 | 後備模型嘅行車時間 |
| C | 每個方向嘅班距時段 | 頂部「班距約 X 分」 |
| F | 首尾班車 | 驗證解析結果 |
| H | **每一班車喺每一個站嘅時間**（平日 527 班、星期六 433 班、星期日 378 班） | 主要定位依據 |

解析驗證：三份時間表首尾班車同 F 部分完全一致（05:45 屯門、05:38 烏溪沙、00:15、00:39）；
0 班車站序錯誤、0 班車時間倒退。

時間表揭示咗 v0.3 無法處理嘅情況：好多班車**唔係由總站開出**——
平日有 18 班由八鄉車廠經錦上路入綫、12 班由荃灣西、11 班由大圍開出；亦有大量短程車（往大圍、紅磡、鑽石山…）。

### 1.2 API 讀數嘅真正意思（實測）

將 2026-10-04 星期日晚 20 個快照、約 4,000 個讀數同 TML7090 逐班對照：

```
ttnt = ceil( (時間表到站時間 + 延誤 − 而家) / 60 )
```

- **「2 分鐘」= 1 分鐘以上、2 分鐘以內到站**，即係向上取整，唔係四捨五入。
  v0.3 當「2 分鐘」= 準時 2 分鐘後到，所以全部列車系統性**遲 30–38 秒**。
- 單一個全綫延誤值已經吻合 85% 讀數；近站（0–2 分鐘）讀數同時間表吻合約 90%。
- `ttnt = 0` 表示列車已到站（停站中）。
- 遠站讀數（3 分鐘以上）有約 10% 會差 ±1 分鐘，所以權重較低。

## 2. 演算法

```
每 20.5 秒（讀晒 27 個站）
  ① 辨認今日用邊份時間表
  ② 每個讀數對應時間表上嘅一班車
  ③ 每班車：由所有讀數求延誤
  ④ 對唔到班次嘅讀數 → 後備模型
每一格畫面（60 fps）
  ⑤ 位置 = 該班車時間表 + 延誤
  ⑥ 平滑：調校列車自身時鐘，唔郁位置
```

### ① 今日時間表

先按日曆揀（平日／星期六／星期日），然後用近站讀數驗證：
每份時間表計「讀數同最近班次相差 ≤ 40 秒」嘅比例。另一份明顯較好（多 25 個百分點以上）就自動轉用。
實測星期日晚：TML7090 **95%**、平日 36%、星期六 27%。公眾假期（行星期日時間表）因此會自動認出，唔使假期表。

### ② 讀數對應班次

- 同一個站、同一方向、**同一目的地**嘅讀數，只會對應目的地相同嘅班次（短程車因此唔會撈亂）。
- 先用全綫近站讀數求「全綫延誤」中位數，再將每個讀數對應到「扣除全綫延誤後」最近嘅班次（±4 分鐘內）。
- 同一個站牌上嘅幾個讀數唔可以對應同一班車。

實測：每個快照 30–32 班車，**100% 讀數都對應到時間表班次**。

### ③ 每班車嘅延誤

由 1.2 嘅規則，每個讀數將該班車嘅延誤限制喺一個 60 秒區間：

```
延誤 ∈ ( 讀數時刻 − 60 − 時間表到站 , 讀數時刻 − 時間表到站 ]
```

一班車通常喺 4–10 個站有讀數，加埋過去 75 秒嘅快照，就有十幾個區間。
取「被最多區間（加權）覆蓋」嘅範圍中點做延誤：近站讀數權重 1、3–5 分鐘 0.4、更遠 0.15；舊快照 × 0.7。
唔同站嘅區間捨入位置唔同，交疊之後通常收窄到 10–20 秒；個別錯配讀數會被多數票否決。

### ④ 後備模型

對唔到任何班次嘅讀數（特別車務、嚴重延誤、時間表以外嘅加班車）用 v0.3 嘅方法：
串連各站讀數 → 擬合起點時間 → 行車模型。行車及停站時間改用**當刻前後 30 分鐘時間表班次嘅實際中位數**（分方向），
再加 API 即時學習嘅修正。實測正常服務下後備模型使用率為 0。

### ⑤ 位置

時間表時刻 `τ = 而家 − 延誤`，喺該班車嘅站表中搵：

| τ 落喺 | 顯示 |
|---|---|
| 首站到站之前 | **唔顯示**（仲喺車廠／側綫） |
| 首站，開車前 | 停喺月台「即將開出」：總站最多提前 5 分鐘（折返停留），車廠出車站 2 分鐘 |
| 兩站之間 | 物理速度曲線：以 1.0 m/s² 加速、巡航、以 1.0 m/s² 制動，巡航速度由站距同時間表行車時間反推（v0.4.6） |
| 中途站，到站至開車 | 停站 |
| 終點到站後 | 停 30 秒後移除 |

每段行車時間、每站停站時間都係**該班車本身**嘅時間表數字（分方向、分時段），唔係平均值。

### ⑥ 平滑（時間域）

新快照改變延誤估算時，**唔改列車位置，改列車時鐘**：
畫面用嘅延誤值以臨界阻尼彈簧追向新估算，速率上限每秒 0.3 秒，即係列車暫時以時間表 0.7–1.3 倍速度行（v0.4.6）。

- 列車永遠唔會倒行、唔會瞬移；
- 唔會「停喺兩站中間」——v0.3 遇到估算落後時會原地凍結等估算追上，即係用戶見到嘅停喺站與站之間；
- 喺站入面只會停耐少少或者短少少。
- 相差超過 150 秒（重新配對）先直接跳過去。

### 延誤標示

時間表班次：延誤 = ③ 嘅估算值（同官方時間表比）。
- 60–179 秒：列車變紅色，標示「+ 75s」；
- 180 秒或以上：列車深紅色加白邊，光暈閃爍（系統設定「減少動態」時改為粗白邊，唔閃）。
後備模型：沿用 v0.3（行車漂移／API 預報／班距）三者取大。
API 嘅 `isdelay = Y` 另以黃框標示。

## 3. 準確度（2026-10-04 星期日 22:40–22:47，20 個真實快照，離線重播）

**方法**：用較早快照預測各站到站時間，同 40 秒至 7 分鐘後快照入面 `ttnt ≤ 1` 嘅讀數比較；
答案按 1.2 取區間中點（讀數時刻 − 30 秒）。答案本身有 ±30 秒捨入，所以誤差中位數嘅下限大約 15 秒。

| 預測距離 | 方法 | 中位誤差 | p90 | RMS | 系統偏差 |
|---|---|---|---|---|---|
| 40–130 秒 | v0.3 | 39.3 s | 69.2 s | 45.2 s | +37.9 s |
| | **v0.4** | **16.0 s** | **34.0 s** | **22.6 s** | **+1.3 s** |
| 2–7 分鐘 | v0.3 | 33.1 s | 67.0 s | 42.4 s | +33.0 s |

**同 API 一致性**：同一快照入面，畫面列車到站時間落喺 API 讀數區間（±35 秒）內嘅比例：v0.3 **57%** → v0.4 **90%**。

**動畫重播**（2,019 格，每格 0.2 秒）：倒行 0 次、單格跳超過 60 m 0 次、

## 3b. 異常情況（v0.4.5）

用 2026-10-04 星期日真實快照，人工注入三種異常測試（「影響」= 其他列車延誤估算變動 > 20 秒嘅次數）：

| 情況 | v0.4.0–0.4.4 | v0.4.5 |
|---|---|---|
| 壞車／收車回廠（讀數消失） | ✅ 自動移除，影響 0 | ✅ 影響 0 |
| 單一列車突然延誤 300 秒 | ❌ 失去班次，13 班受影響（最多 127 秒） | ✅ 保持班次，估算 301 秒，影響 0 |
| 單一列車逐步延誤（每快照 +25 秒） | — | ✅ 全程追蹤（估 306 秒，真值 350 秒，稍為滯後），影響 0 |
| 時間表以外加車 | ❌ 20 班受影響（最多 222 秒） | ✅ 交後備模型，影響 0 |

改動：
1. **追蹤**：每班車用自己上一次嘅延誤做預期，唔再用全綫平均；被扣車嘅列車可以比預期遲最多 10 分鐘仍保持身份。
2. **順序對齊**：每個站牌嘅讀數同時間表班次做「唔交叉」嘅最佳對齊（動態規劃），配唔到嘅讀數明確交後備模型，唔會連鎖推錯其他列車。窗口由 ±240 秒收窄到 ±150 秒。
3. **繁忙時段埋堆**：2026-10-05 平日早繁實測，列車埋堆令站牌出現 2 分鐘間隔（時間表 3 分鐘）。
   落喺兩個班次之間嘅讀數，如果符合某班已定位列車自己嘅延誤（±90 秒），就併入嗰班，唔另開一班。
4. **去重**：同方向兩列車距離 < 0.85 km 視為同一列車（重新配對後嘅舊班次、或後備模型由零散讀數砌出嘅列車）。
   後備模型最少要 2 個一致讀數先會畫一列車。舊班次冇讀數時保留時間由 90 秒減到 45 秒（駛入總站最後一段除外）。
   早繁實測：顯示列車由 56 班（比時間表多 6 班重複）改善為 48–50 班（時間表 50–51 班行駛中）。

早繁 4 個快照嘅準確度：預測中位誤差 23.5 秒、同 API 一致性 81%（星期日晚 16.0 秒、90%）。
埋堆令個別列車難以分辨係邊一班，誤差尾段較長；需要更多繁忙時段數據再調整。

## 3c. v0.4.6 修訂（評估外部研究報告後）

| 報告建議 | 核實結果 | 處理 |

| 七段急衝度（jerk）曲線 | 同梯形比差距只係幾米，冇數據可驗證 | 唔採用 |
| 0.85 km 固定去重會誤殺埋堆列車 | **方向啱**：距離唔係證據 | 改為**證據去重**：候選列車嘅每一個讀數，都要被一列已定位列車嘅預計到站時間解釋到（±75 秒）先當重複；純距離只喺 < 0.25 km（一列車長 + 排隊間隙）先生效 |

| 中途折返要「停 180 秒再反方向」 | 冇數據支持呢個數字 | 唔採用：API 每個讀數都有 `dest`，折返後回程列車會以新讀數出現 |

驗證（真實數據重播）：星期日晚 + 平日 14:35 兩組，倒行 0、行車中停定 0、顯示列車數 = 時間表行駛中班數（平日 22 = 22）、
星期日預測中位誤差維持 16.0 秒。

## 3d. 總站折返（v0.4.8）

時間表顯示，三份時間表**所有**到達屯門／烏溪沙嘅班次（平日 450、星期六 391、星期日 350）都會以**同一個 Run 編號**由同一個總站開出回程，
停留中位約 220–247 秒（最短 64 秒、最長約 10 分鐘），任何時候最多 2 列同時停喺總站（屯門、烏溪沙各有 2 個月台）。

v0.4.7 之前：到站列車 30 秒後消失，回程班次要到開出一刻先出現，中間成段折返時間總站冇車。
v0.4.8：按 Run 編號將到站班次同回程班次連起嚟——到站後列車停喺月台，即時交接俾同一 Run 嘅回程班次，
回程開車時間由總站站牌嘅出發倒數決定；列車未到站前，回程班次唔會提早出現（唔會一列車畫兩次）。

另外修正：站牌喺列車停站（甚至開出後）會持續顯示「0 分鐘」，舊算法將每個「0」都當「啱啱到站」，
令駛向總站嘅列車延誤每次更新加約 10 秒（實測 27 → 60 秒）。而家「0 分鐘」只取**第一次**出現嘅時間。

實測（平日 17:20–17:23）：Run 18 由兆康駛入屯門延誤維持 27 秒、到站即交接到 2 號月台回程列車；
畫面列車 44 列 = 時間表（行車中 + 總站停留）44 列；同一 Run 從未同時出現兩次；總站同時停留最多 2 列。

## 3e. 時間表清單、時間表唔吻合偵測、倒數模式（v0.5.0）

**時間表清單**：`data/timetables/index.json` 列出所有可用時間表（代號、檔案、日子類型、平常／特別、生效日期）。
App 先載入日曆對應嗰份，其餘喺背景載入，載入後成為候選。新增時間表只需執行 `tools/parse_timetables.py`，
佢會先用 `tools/validate_timetable.py` 檢查，通過先登記。

檔案格式（每份）：
```
{ "timetable": "TML1100B", "day": "weekday|saturday|sunday|special",
  "sectionA": {"DOWN": {"periods": [...], "hops": [{"from","to","km","cols":[行車,停站,...]}]}, "UP": {...}},
  "headways": {"DOWN": [{"from":"07:45","to":"08:45","headway":163}], "UP": [...]},
  "trips": [{"dir":"UP","run":16,"trip":"10053","notes":[],"stops":[["WKS",null,24870],["MOS",24990,25013], ...]}] }
```
時間 = 服務日（04:00 起計）零時後秒數；過咗午夜 > 86400。

**時間表唔吻合偵測**（每次更新計算）：
1. 讀數配得到時間表班次嘅比例 < 50%（單獨已足夠）；
2. 已配對列車中 > 20% 偏離時間表超過 120 秒；
3. 由站牌實測班距同時間表班距相差 > 30%（上行或下行）；
4. 站牌訊息提到特別車務安排。

條件 1，或者 2–4 中最少兩項成立，連續 2 次 → 轉「按到站倒數推算」模式；連續 3 次唔成立 → 轉返時間表。
轉入倒數模式時即刻清除所有按時間表配對嘅列車，唔會殘留錯誤延誤。

實測（真實數據重播）：正確時間表 0/20、0/4 次誤轉；時間表錯位 3 小時（冇班次對得上）20/20、4/4 次正確轉換。
**限制**：同正常時間表好相似嘅特別時間表（例如夜間 6–7 分鐘班距）唔會被偵測到；
呢種情況列車位置仍然由倒數決定，但個別列車嘅「+Xs」延誤可能唔準。

**倒數模式**：只用港鐵 API —— 列車位置由各站倒數串連推算；行車時間用基本模型 + 由 API 即時學習；
頂部顯示上下行列車數同實測班距；車次、Run 編號、時間表延誤顯示 N/A；
同前車距離比實測班距長 60 秒以上嘅列車顯示黃色「班距 +Xs」（唔叫「延誤」，因為冇時間表可比）。
延誤標示改為「+ 60s」（遲 = 正數）。

## 4. 已知限制

- 冇真實列車位置可對答案；準確度係「同港鐵之後嘅倒數比」。
- 個別列車遲超過半個班距（約 3 分鐘）時，可能被當成下一班車：位置仍然正確，但「Delay」數字會偏細。
- 時間表要人手更新：港鐵出新版（例如 TML1100C）時，用 `tools/parse_timetables.py` 重新生成。
- 特別車務（賽馬、颱風、活動）有獨立時間表；冇嗰份時間表時會落後備模型。
